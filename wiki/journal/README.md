# journal 작성 규칙

> 세션 작업 일지. **journal 자체가 이력이다 — 색인·매핑 표를 두지 않는다**(세션↔커밋 매핑은 `git log -- wiki/journal/YYYY-MM/`). 이 README는 작성 규칙 전용이며 정책 변경 시에만 수정한다.

## 경로·채번

- `wiki/journal/YYYY-MM/r{NNN}-{slug}.md` (KST 기준 월). 월 폴더는 첫 작성 시 생성.
- 리비전은 해당 월 내 1씩 증가, **월이 바뀌면 r001부터 재시작**. 3자리 zero-pad.
- 외부 참조는 항상 `YYYY-MM/r{NNN}` 풀 경로.
- slug: ASCII kebab-case 2~5단어(`a-z 0-9 -`). 공백·대문자·한글·특수문자 금지.
- **병행 세션 채번 가드**: 여러 CLI를 병행하면 같은 번호를 독립 채번해 충돌하기 쉽다 — 작성 직전 해당 월 디렉토리에서 최대 리비전을 확인해 +1로 채번하고, 충돌 발견 시 나중 세션이 뒤 번호로 재명명한다(파일명 + `문서리비전` 필드 동기).

## 문서 상단 형식

```markdown
# r{NNN} — {한글 제목}

| 항목 | 값 |
|---|---|
| 문서리비전 | r{NNN}-{slug} |
| 작성일시 | YYYY-MM-DD HH:MM (KST) |
| 작성모델 | {메인 세션 모델} |
| 담당에이전트 | {세션 주도 에이전트} |
```

- 문서 첫 줄은 H1 제목이고 바로 아래에 렌더링되는 Markdown 메타데이터 표를 둔다. 신규 journal의 YAML `---` frontmatter는 금지한다.
- 표의 4필드는 대체·추가하지 않는다. 위임 작업이면 작성모델에 `메인모델 + 실행 에이전트모델`을 병기한다.

## 본문 섹션

- **필수 4**: `## 요약`(한 일) / `## 커밋 (이번 세션)` / `## 다음 우선순위` / `## 자가점검 회고`
- **조건부(해당 시만)**: `## 결정/판단 근거` / `## 미해결 이슈` / `## 검증` / `## 작업번호`(지시서·작업 완료 시)
- 도메인 추가 섹션 허용.

## 운영

- 한 번 작성한 파일은 수정하지 않는다(스냅샷 보존). 추가 작업이 생기면 다음 r번호 신규 파일. pre-compact 자동 스냅샷(`r{NNN}-snapshot.md`)은 정식 슬러그 재명명 후 본문 작성 허용.
- r{NNN} 스냅샷은 wrap-up에서 수동 기록만(작업 중 갱신은 CURRENT.md — 아래 §작업 저널) — 훅 자동 기록 금지(훅 세션 로그가 필요하면 gitignored 별도 파일로).
- SessionStart 훅이 최신 `YYYY-MM/`의 최신 `r{NNN}-*.md`를 자동 탐지해 **경로 포인터 한 줄로** 출력한다(전문 덤프 아님 — CURRENT.md와 중복이라 축약). 필요할 때만 직접 Read한다.
- 직전 journal 포인터는 훅이 파일시스템에서 자동 산출한다 — 문서에 수동 유지하지 않는다.
- 비밀·키 평문 금지.

## 레거시

- 기존 YAML frontmatter journal은 작성 시점 스냅샷으로 보존하고 소급 수정하지 않는다.

## 작업 저널 (CURRENT.md — 혼합형)

- `CURRENT.md`(이 디렉토리 직속)는 살아있는 작업 저널이다 — r{NNN} 스냅샷과 달리 **수정 자유**(스냅샷 보존 예외). 저널은 대화 기록·작업 일지가 아니라 현재 작업 상태를 다음 작업자와 에이전트에게 정확히 전달하는 문서다.
- **SessionStart 훅은 이 파일의 압축 브리프만 매 세션 주입한다** — GOAL 1, STATE 2, OPEN 2, NEXT 3을 원문 포인터와 함께 UTF-8 4KiB 이내로 출력한다. 항목을 중간에서 자르지 않으며 개수와 예산으로 생략한 내용은 명시한다. 구조 오류와 원문 부재도 원문 확인 안내로 표시한다. 상세와 완료 근거는 `r{NNN}` 스냅샷이 SSOT이며, 필요할 때 `SOURCE` 원문 fallback을 Read한다. 권고 상한은 **≤10KB**다.
- `wiki/INDEX.md`는 **항행 인덱스 + durable 레지스트리 전용**이라 진행 상태를 두지 않는다 — 진행 상태의 단일 SSOT는 이 `CURRENT.md`다.
- **작업 중 즉시 갱신 조건**(턴 단위 기록 금지 — 의미 있는 상태 변화만): 요구사항·작업 범위 확정/변경 · 설계 결정 · 파일 실제 생성/수정/이동/삭제 · 테스트/빌드/린트/실행 결과 확인 · 오류/회귀/차단 요소/외부 의존성 발견 · 계획 폐기/접근 변경 · 병렬 작업자 공유 전제 · 세션 중단 시 복구 곤란 정보.
- **기록 금지**: 단순 탐색·파일 열람, 미채택 아이디어, 미확인 추측, 같은 상태의 표현만 바꾼 반복, 대화 전문, 코드로 자명한 사소한 구현 과정, 비밀값·키·토큰·개인정보.
- 항목 형식: `대상 + 확인된 상태 + 필요한 후속 조치` (예: "`tests/test_path.py`의 UNC 경로 테스트가 실패함. 경로 구분자 정규화 로직 확인 필요.").
- **상태 표현**: `완료`(구현+검증 모두 끝) / `부분 완료` / `미완료` / `차단` / `미검증`(변경했으나 실행 결과 미확인). 확인된 사실과 예상·추정은 분리 표기하고, 예상 원인을 사실처럼 기록하지 않는다. 테스트를 실행하지 않고 통과로 기록하지 않는다.
- **병렬 작업 시 즉시 기록**: 작업 중 파일·범위, 공통 인터페이스/데이터 구조 변경, 다른 작업에 영향을 주는 결정, 재사용 금지인 실패한 접근, 머지/충돌 가능 변경. 에이전트가 무엇을 하고 있다는 사실만은 기록하지 않는다.
- **wrap-up 절차**: (1) CURRENT.md 전체 재검토 — 완료 메모 반영, 중복·무효 계획 제거, 폐기 접근은 결정 근거로 필요한 경우만 유지, 완료/미완료/차단 구분, 미검증은 완료 표시 금지, 다음 작업 구체화, repo 상태와 일치 확인. (2) 정제 결과를 바탕으로 r{NNN} 스냅샷 작성(위 규칙 그대로). (3) CURRENT.md는 미해결·다음 작업 중심으로 정리한다(완료 상세는 r{NNN}이 보유 — 누적 금지).
- CURRENT.md 골격: `## 목표` / `## 현재 상태` / `## 주요 결정` / `## 검증 결과` / `## 미해결 사항` / `## 다음 작업`.
