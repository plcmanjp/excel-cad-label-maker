## 요약

[Issue #2](https://github.com/plcmanjp/excel-cad-label-maker/issues/2)와 공개 원격 저장소를 읽고 기준 main과 로컬 HEAD가 같은 상태에서 승인된 UX 구현을 진행했다. 원본 소스와 0.1.0 EXE 및 릴리스 manifest는 보존하고 별도 src/에 열 방향 라벨 읽기와 가변 높이 DXF 배치 및 Tk UI를 복구했다.

Python 3.13.15 `.venv`, 직접 및 간접 의존성 잠금, 소스 실행, Windows 무설치 개발 빌드와 고지를 구성했다. 처음 잘못 생성한 `.ven`은 이번 세션이 만든 대상과 프로세스 및 링크 부재, 재생성 근거를 확인하고 `.venv`로 대체한 뒤 제거했다.

앱 전체에서 Excel 한 개를 드래그 앤 드롭할 수 있고 파일 찾기도 유지한다. Tcl 경로 목록을 해석해 한글, 공백과 중괄호를 지원한다. 여러 파일, 다른 확장자, Excel 임시 파일과 없는 경로는 거부하며 기존 선택을 보존한다. DXF는 R2010, UTF-8, mm 단위로 저장한다.

## 검증

- 제품 회귀 18개, 하네스 22개, 기준 릴리스 경계 6개 및 빌드 거부 검사 2개(3조건)가 통과했다. 공개 경계, 원본 hash, UTF-8, 표시 구두점, 의존성 검사와 diff whitespace 검사도 통과했다.
- 원본 0.1.0 앱과 개발 앱의 정확한 창을 컴퓨터 유즈로 캡처해 확인했다. 개발 EXE에서 합성 `.xlsx`를 탐색기에서 실제 드래그하고 선택 완료 및 생성 버튼 활성화를 확인했다. 입력 파일 찾기 대화상자는 사용하지 않았다.
- 탐색기 상세 보기의 파일 항목 중심이 창 밖으로 계산되어 공용 입력 보호가 첫 시도를 거부했다. 큰 아이콘 보기로 실제 항목 중심이 창 안에 있는 상태를 관찰한 뒤 단일 드래그가 완료됐다. 도구의 전달 완료와 앱의 수용 관찰은 구분했다.
- 같은 EXE의 생성 및 저장 대화상자로 DXF를 저장했다. 라벨 4개, TEXT 7개와 닫힌 LWPOLYLINE 7개를 확인했고 한글 및 영문 재읽기가 정확하며 ezdxf audit 오류는 0개다.
- 실제 검수 EXE 및 최종 고지 포함 빌드 EXE의 SHA-256은 795b8293bbd4e50097c15c512358a2aeb744e59d7d1d34c92055b36dd20f5dc0으로 같다. 합성 파일, 엔진, 소스와 출력 hash 및 검증 범위는 `qc/development-build.json`에 있다. 개인 경로와 원시 UIA 기록은 `.local/`에만 보관했다.
- 외부 고지 원문 63개의 출처 hash와 빌드 receipt의 1,900개 파일 hash를 확인했다. 원본 EXE 포함 라이브러리를 확인한 결과로 표현하지 않는다.
- OneDrive 읽기 전용 생성 디렉터리로 재빌드가 실패해 경로 검사를 통과한 생성 디렉터리만 속성을 처리하도록 보정하고 재빌드가 통과했다. 실행 중 앱 거부와 dist/build 조상 및 자식 junction/symlink 거부를 추가했다.
- 읽기 전용 code-reviewer가 CI native 실패 전달과 조상 junction 보호 두 항목을 지적했다. CI는 검증된 빌드 스크립트를 재사용하고 EXE 없는 receipt를 거부하도록 보정했다. 기존 지적의 delta 검수에서 모두 해결로 확인했다.

## 미해결 이슈

- 실제 CAD 열기와 글꼴 렌더링, 원본 소스와 기존 EXE의 대응 관계, 기존 EXE의 포함 라이브러리 및 구체적인 원본 이용 조건은 미확인이다. DWG 직접 출력은 미지원이다.
- Python이 없는 별도 PC에서 개발 앱 실행은 별도 확인 대상이다. 깨끗한 Windows 빌드의 CI 결과는 GitHub Actions에서 해당 commit으로 확인한다.
- Issue #2의 전체 수용 조건은 남아 있으므로 닫지 않는다. 이번 요청의 Issue 검토와 제품 구현을 원격 Issue 본문 또는 댓글 변경 승인으로 확대하지 않았다.

자동화 검사, 실제 탐색기 파일 전달, 앱 선택 수용, EXE의 저장 결과와 CAD 검증을 각각 구분했다. 원본의 출처와 권리 범위를 유지하며 후속 구현을 원본 EXE의 동일 재빌드라고 주장하지 않는다. 빌드 실패 보정은 원인 측정과 보호 검사 및 독립 delta 검수로 마무리했다.
