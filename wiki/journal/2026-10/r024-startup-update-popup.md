## 검증

- Windows 11 x64, Python 3.13.15와 Tk 8.6 및 고정 의존성, OneDrive 밖 독립 checkout과 격리 설정에서 진행했다.
- 알림 회귀 10개 PASS. 예약된 시작 조회와 단일 창, 수동 캐시 재열기, defer scope와 실제 Tk grab 해제 후 팝업, 최신/실패의 자동 침묵과 수동 피드백, 창 배치와 종료 후 worker를 검사했다.
- 표준 build-dev.ps1에서 전체 제품 130개 PASS 및 개발용 빌드/아이콘/법적 고지 PASS. 별도 build-update-qc.ps1도 PASS다. 두 receipt는 source_dirty=false, 각 1,126파일과 모든 소스/산출물 hash 및 LICENSE 원문 byte 일치다.
- 소스 및 frozen QC EXE를 실제 GitHub API와 비교 버전 0.0.1로 시작해 공개 0.4.1을 찾은 직후 수동 클릭 없이 팝업이 보이는 것을 Computer Use로 확인했다. Escape와 나중에 닫기, 수동 버튼 재열기도 확인했다.
- 일반 개발 EXE는 정상 버전 0.4.1로 실행되며 자동 새 버전 팝업이 없고 수동 조회에서 더 새로운 정식 버전 없음 안내를 표시했다. 비교 버전 override는 정상 앱에 추가하지 않았다.
- 개발 EXE SHA-256은 `b03f363443e2499325fab9df92007843786e7363d677734254b00177e4aa1bbf`, 별도 QC EXE는 `d1d33c55469cfaa79f9874a200bb5677557477306fd86bda2a08c055ec5a2267`이다.
- 최초 빌드 호출은 PowerShell의 stderr 병합이 unittest 진행 출력을 오류로 바꿔 중단했다. 별도 PowerShell 프로세스로 표준 명령을 실행한 결과 130개가 통과했고 전체 로그를 보존했다. 제품 assertion 실패로 판정하지 않았다.
- 자동화의 부모 창 포커스와 native UIA cache 때문에 최초 키/클릭 일부는 닫기를 수행하지 못했다. 최신 state에서 해당 팝업을 Raise한 뒤 정상 Escape/Return 닫기와 상태 해제를 확인했다. 도구 문제를 제품 성공으로 덮거나 다른 UIA 엔진으로 우회하지 않았다.
- 저장소/공개 문서 및 diff 검사 PASS. 정식 0.4.1 ZIP hash는 기존 `046716e73c0c350245da02858fc2e25c6869d9ab11bdc55871399ccf459bfc16`으로 유지한다.

## 미해결 이슈

- 새 정식 배포와 main 병합은 수행하지 않았다. 실제 native 파일 대화상자 타이밍과 물리적 네트워크 차단은 재검증하지 않았고 실제 Tk grab 및 결정적 실패 검사를 별도로 기록했다.
- 청소와 실제 CAD/OS 현장 검증은 기존 이슈 범위다.
